# GH-SHOC — Algorithm Trace Tables (Section 7 evidence)

All traces below were generated by running the actual instrumented code in
`ghshoc.trace.TraceGenerator` (see `src/main/java/ghshoc/trace/`), not
worked out by hand — so they're guaranteed to match what the real
implementation does. Include these tables directly in your report; you
can re-run the generator yourself to verify.

## 1. Binary Search
Input: `[10, 20, 30, 40, 50, 60, 70]`, target = `60`

| Step | lo | hi | mid | arr[mid] | Decision |
|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 40 | 40 < 60 → search right half, lo = mid+1 = 4 |
| 2 | 4 | 6 | 5 | 60 | 60 == 60 → **FOUND at index 5** |

**Complexity:** O(log n) — each step halves the search space. For n = 7,
⌈log₂7⌉ = 3 steps maximum; this run took 2.

## 2. Insertion Sort
Input: `[8, 3, 7, 4, 2]`

| i | key | Array state after this pass |
|---|---|---|
| — | — | `[8, 3, 7, 4, 2]` (initial) |
| 1 | 3 | `[3, 8, 7, 4, 2]` |
| 2 | 7 | `[3, 7, 8, 4, 2]` |
| 3 | 4 | `[3, 4, 7, 8, 2]` |
| 4 | 2 | `[2, 3, 4, 7, 8]` |

**Complexity:** O(n²) worst/average case (reverse-sorted input), O(n) best
case (already sorted — inner while-loop never executes).

---

## 3. Merge Sort (one merge step)
Input: `[38, 27, 43, 3]`

Split phase: `[38, 27]` and `[43, 3]`, recursively sorted to `[27, 38]` and `[3, 43]`.

Merge phase — compare heads of each half, take the smaller, advance that pointer:

| Comparison | left[i] | right[j] | Taken | Result so far |
|---|---|---|---|---|
| 1 | 27 | 3 | 3 | `[3]` |
| 2 | 27 | 43 | 27 | `[3, 27]` |
| 3 | 38 | 43 | 38 | `[3, 27, 38]` |
| — | — | — | 43 (right exhausted, flush remainder) | `[3, 27, 38, 43]` |

**Complexity:** O(n log n) in all cases (splitting is always balanced,
merging is always linear) — this is why it's the reliable choice when
worst-case guarantees matter more than average-case speed, at the cost of
O(n) auxiliary space.

## How to regenerate / extend these traces
```
javac -d out src/main/java/ghshoc/trace/TraceGenerator.java
java -cp out ghshoc.trace.TraceGenerator
```
Edit the arrays inside `TraceGenerator.main` to trace different inputs
(e.g. an already-sorted array to demonstrate insertion sort's best case,
or a reverse-sorted array to demonstrate its worst case) and re-run.
